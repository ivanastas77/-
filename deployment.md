1) Общие сведения
Данный документ содержит рекомендации по внедрению и эксплуатации программного средства шифрования и расшифрования данных на основе алгоритма PIKE. Программа предназначена для локального использования в 
учебных и демонстрационных целях, а также для ознакомления с принципами работы блочных алгоритмов шифрования.
Файл программы: pike.py
Файл с документацией и инструкциями: deployment.md

2) Сценарии внедрения

Программное средство может использоваться в следующих случаях:
1.Учебные цели 
2.использование в аудиториях и компьютерных классах для изучения дисциплин по информационной безопасности и криптографии;
3.демонстрация работы блочных алгоритмов шифрования, включая PIKE.
4. Демонстрационные цели
5.показ работы алгоритма PIKE на текстовых данных;
6.анализ процесса шифрования и расшифрования блоков данных.
7.Локальное шифрование текстовых данных
8.защита информации без передачи по сети;
9.возможность использования для экспериментов и тестирования.

3) Требования к программно-аппаратной среде
Для корректной работы программы требуется минимальная программно-аппаратная конфигурация:
1.Операционные системы: Windows, macOS, Linux;
2.Интерпретатор Python: версия 3.9 и выше;
3.Графический интерфейс: библиотека Tkinter (входит в стандартную поставку Python).

4) Ограничения использования
1.Программа предназначена исключительно для учебных и демонстрационных целей.
2.Не рекомендуется использовать для защиты критически важной или конфиденциальной информации.
3.Ключ шифрования должен храниться пользователем в защищённом виде и не передаваться третьим лицам.

5) Рекомендации по эксплуатации

1.Перед началом работы убедиться, что установлен Python версии 3.9 и выше.
2.Запуск программы производится командой:
3.python pike.py
4.Использовать кнопку «Шифровать» для получения зашифрованного текста и «Расшифровать» для восстановления исходного текста.
5.Для очистки всех полей использовать кнопку «0».
6.Ключ шифрования хранить в безопасном месте и не передавать третьим лицам.

Контроль и поддержка

1.Все изменения программы и документации должны фиксироваться в системе контроля версий Git.
2.При обнаружении ошибок необходимо провести корректировку кода и повторное тестирование.
3.Текущий файл deployment.md должен оставаться актуальным и отражать все изменения в процессе эксплуатации.
